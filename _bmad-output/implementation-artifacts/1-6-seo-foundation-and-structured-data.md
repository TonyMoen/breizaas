## User Story

**As a** search engine
**I want** to crawl and index the Breizaas website with proper Norwegian metadata and structured data
**So that** the website appears correctly in Norwegian search results with rich snippets

## Business Value

This story creates the invisible but critical SEO infrastructure that enables Breizaas to be discovered organically through Norwegian search queries. Without proper SEO foundation, the beautifully designed website remains invisible to potential fans searching for "AI musikk Norge", "bygdemusikk AI", or "Breizaas".

**Impact:** Essential for:
- **Organic Discovery**: 70%+ of website traffic comes from search engines - proper SEO is the primary discovery channel
- **Norwegian Market Positioning**: Optimized Norwegian metadata ensures Breizaas appears in local search results, not buried beneath international artists
- **Rich Snippets**: Structured data (MusicGroup, Event schemas) makes search results more compelling with star ratings, tour dates, and listener counts
- **Social Sharing**: Open Graph tags ensure Instagram/Facebook shares show proper preview images and descriptions instead of generic placeholders
- **Artist Credibility**: Professional SEO signals quality and legitimacy to both users and search engines
- **Long-term Traffic Growth**: SEO compounds over time - every indexed page increases future traffic potential

**Priority:** CRITICAL - Zero organic traffic without proper SEO. Must be implemented before launch.

## Context & Background

### The SEO Challenge for Breizaas

**Unique Positioning Challenges:**
1. **Novel Concept**: "AI-generated bygdemusikk artist" - no existing search patterns
2. **Norwegian Language Market**: Must rank in nb-NO search results, not just global
3. **Genre Niche**: Bygdemusikk is a specific Norwegian music category with dedicated searchers
4. **Competition**: Competing against established artists and Spotify playlists
5. **Credibility Signal**: 125k listeners is proof of legitimacy - needs visibility in search

**Search Intent Analysis:**

**Informational Searches (Awareness):**
- "hva er AI musikk" (what is AI music)
- "AI-generert musikk Norge" (AI-generated music Norway)
- "hvordan lages AI musikk" (how is AI music made)

**Artist Discovery Searches:**
- "Breizaas" (brand search - most important)
- "Breizaas musikk" (Breizaas music)
- "Breizaas Spotify" (platform-specific)

**Genre Searches (High Intent):**
- "norsk bygdemusikk 2025" (Norwegian rural music 2025)
- "festmusikk Norge" (party music Norway)
- "beste bygdemusikk artister" (best rural music artists)

**Event Organizer Searches:**
- "book bygdemusikk artist" (booking intent)
- "festmusikk til arrangement" (party music for events)
- "norsk artist booking" (Norwegian artist booking)

### How Search Engines Understand Breizaas

**Without Structured Data (Current State):**
- Search engine sees: "Some Norwegian text about music"
- No understanding that Breizaas is a music artist
- No connection between Breizaas and social profiles
- No rich results - just plain text snippet
- Page rank determined only by content keywords

**With Proper SEO (Goal State):**
- Search engine understands: "MusicGroup entity named Breizaas, genre: bygdemusikk"
- Knows Spotify profile, Instagram, social links are all the same entity
- Can show rich results: ⭐ ratings, 📍 tour dates, 🎵 sample tracks
- Norwegian language signals boost local rankings
- Proper meta descriptions increase click-through rate

### SEO Technical Requirements

**Meta Tags:**
- `<html lang="nb-NO">` - Tells search engines content is Norwegian Bokmål
- Title tags: Unique per page, includes keywords + branding
- Meta descriptions: 150-160 characters, compelling, keyword-rich
- Canonical URLs: Prevents duplicate content issues
- Open Graph tags: Controls social sharing appearance

**Structured Data (Schema.org):**
- **MusicGroup**: Artist profile (name, genre, social links)
- **Event**: Tour dates with dates, venues, ticket links (Future: Epic 3)
- **Product**: Merchandise listings (Future: Epic 4)
- **Organization**: Brand identity, contact info

**Technical SEO:**
- sitemap.xml: Auto-generated from Next.js routes
- robots.txt: Allow all public pages, disallow nothing
- Page speed: < 2s load time (already met in previous stories)
- Mobile-first: Responsive design (already implemented)
- HTTPS: Handled by Vercel hosting (future deployment)

### Sitemap Generation

**Dynamic Sitemap (`src/app/sitemap.ts`):**
```typescript
import { MetadataRoute } from 'next'

export default function sitemap(): MetadataRoute.Sitemap {
  const baseUrl = 'https://breizaas.no'

  const routes = [
    '',
    '/musikk',
    '/konserter',
    '/merch',
    '/om-oss',
    '/kontakt',
    '/arrangor',
  ]

  return routes.map((route) => ({
    url: `${baseUrl}${route}`,
    lastModified: new Date(),
    changeFrequency: route === '' ? 'daily' : 'weekly',
    priority: route === '' ? 1.0 : route === '/om-oss' ? 0.9 : 0.8,
  }))
}
```

## Latest Technical Specifications (2025)

### Next.js Metadata API (Next.js 16)

**Global Metadata in Root Layout:**
```typescript
// src/app/layout.tsx
export const metadata: Metadata = {
  metadataBase: new URL('https://example.com'),
  title: {
    default: 'Default Title',
    template: '%s | Brand'
  },
  // ...
}
```

**How Title Template Works:**
- Default: Used when page has no title → "Default Title"
- Template: Applied to page-specific titles → "Page Title | Brand"
- Page without title uses default, page with title uses template

**metadataBase Purpose:**
- Resolves relative URLs in Open Graph images
- Required for canonical URLs to work correctly
- Sets base for all absolute URL generation

**Sources:**
- [Metadata API - Next.js 16 Docs](https://nextjs.org/docs/app/api-reference/functions/metadata)
- [Metadata Files - Next.js](https://nextjs.org/docs/app/api-reference/file-conventions/metadata)

### Dynamic sitemap.ts and robots.ts (Next.js 16)

**Sitemap Generation:**
```typescript
// src/app/sitemap.ts
import { MetadataRoute } from 'next'

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    {
      url: 'https://example.com',
      lastModified: new Date(),
      changeFrequency: 'daily',
      priority: 1.0,
    },
  ]
}
```

**Robots.txt Generation:**
```typescript
// src/app/robots.ts
import { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: '*',
      allow: '/',
    },
    sitemap: 'https://example.com/sitemap.xml',
  }
}
```

**Automatic Routes:**
- sitemap.ts creates /sitemap.xml
- robots.ts creates /robots.txt
- Generated at build time
- Served statically

**Sources:**
- [sitemap.xml - Next.js](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap)
- [robots.txt - Next.js](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/robots)

### Schema.org MusicGroup (2025)

**Required Properties:**
- @context: "https://schema.org"
- @type: "MusicGroup"
- name: Artist name

**Recommended Properties:**
- genre: Array of genres
- description: Brief bio
- url: Official website
- sameAs: Social media profiles array
- image: Artist photo URL

**Optional but Valuable:**
- aggregateRating: Ratings from platforms
- member: Band members (if applicable)
- album: Discography (for more complex schemas)

**Google's Understanding:**
- Recognizes entity as music artist
- Connects social profiles to artist
- Enables Knowledge Panel in search results
- Can show in music-related queries

**Sources:**
